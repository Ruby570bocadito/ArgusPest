ARGOS: Plataforma de Operaciones Ofensivas Autónoma
"El humano marca el objetivo; Argos traza y ejecuta el camino."
1. Filosofía y Principios
Autonomía total con supervisión opcional: Argos toma decisiones tácticas sin preguntar; el operador solo interviene si quiere o si el riesgo supera un umbral configurado.

Razonamiento híbrido ligero: combina planificación de grafos (A*), memoria de casos (Case-Based Reasoning) y reglas expertas. Corre en cualquier portátil, sin GPU.

Paralelismo masivo: despliega agentes concurrentes en distintos flancos del objetivo, orquestados por un director central.

Arsenal propio: fábrica de malware modular (rootkits, RATs, virus, troyanos, spyware, exploits, webshells) compilado bajo demanda con ofuscación avanzada.

Evasión integrada: desde la generación del binario hasta el tráfico de red, todo se adapta al contexto (EDR detectado, entorno, perfil de misión).

Primero la terminal: interfaz CLI rápida y scripteable, con modo TUI inmersivo opcional.

2. Motor de Decisión Híbrido (sin LLM)
2.1 Componentes
Componente	Entrada	Salida	Tecnología
Planificador A*	Grafo Vivo (hosts, servicios, creds, defensas)	Ruta(s) óptima(s) hacia el objetivo	NetworkX, heurística personalizada
Razonador por Casos (CBR)	Embeddings del servicio/vulnerabilidad actual	Top-k acciones similares del pasado con tasas de éxito	Qdrant (vector DB), Sentence-Transformers (modelo mini)
Motor de Reglas Heurísticas	Árboles de decisión por tipo de servicio/OS/defensa	Acciones tácticas concretas (fuerza bruta, CVE específica, evasión)	Python, anytree
El Fusionador de Decisiones recoge las sugerencias de los tres, calcula una puntuación ponderada y determina la acción final. Si la confianza supera el umbral del perfil activo (Ghost/Balanced/Blitz), se ejecuta; si no, se encola para el operador.

2.2 Funcionamiento del Razonador por Casos (CBR)
En la fase de reconocimiento, cada servicio se convierte en un vector con un modelo ligero de embeddings (all-MiniLM-L6-v2, 80 MB, CPU).

Se busca en Qdrant los 5 vectores más cercanos de misiones anteriores.

Se extraen las acciones asociadas (exploit usado, credenciales probadas, payloads) y se ordenan por éxito / intentos.

La mejor opción se propone al fusionador. Si falla, se prueba la siguiente automáticamente.

2.3 Ejemplo de razonamiento sin LLM
Escenario: descubrimos un IIS 10.0 con cabecera Server: Microsoft-IIS/10.0 y puerto 8172 (Web Deploy).

Planificador A*: "IIS puede ser puerta de entrada a la intranet. La ruta más corta al DC pasa por obtener RCE aquí."

CBR: busca en memoria casos similares. Encuentra que en dos misiones pasadas Web Deploy se explotó con credenciales por defecto (admin:admin) y en otra con un CVE de deserialización. Sugiere probar credenciales por defecto (éxito 66%).

Motor de Reglas: "Si Web Deploy y EDR es Defender, intentar credenciales por defecto; si falla, CVE-2024-xxxx con payload en memoria."

Fusionador: probabilidad compuesta 0.78. Se ejecuta fuerza bruta de credenciales sin preguntar.

4.2 Modo TUI
Al ejecutar argos status, se abre una interfaz dividida:

Panel izquierdo: Grafo Vivo simplificado (árbol de nodos con colores por estado).

Panel central: Línea de tiempo de eventos (últimos scans, exploits, credenciales).

Panel derecho: Cola de decisiones y atajos de teclado.

Barra superior: misión activa, perfil, GDS, agentes vivos.

Navegación con teclas (Tab para cambiar panel, Enter para decidir, q para salir).

5. Grafo Vivo (Knowledge Tree)
Representa todo lo que Argos sabe. Se implementa con NetworkX y se persiste en SQLite.

Tipos de nodos:

Host: ip, hostname, os, arquitectura, rol, asset_value.

Service: puerto, protocolo, banner, versión, cpe.

Credential: usuario, tipo (password, hash, ticket), ámbito.

Vulnerability: cve, cvss, vector, exploit asociado.

Flag: valor, timestamp.

Defense: edr (crowdstrike, defender...), waf, ids, honeypot.

GlobalDefenseState: único nodo con score 0.0-1.0 que se propaga a todo el grafo.

Aristas:

EXPLOITS (Host1 -> Host2) : si desde Host1 se puede explotar Host2.

HAS_SERVICE (Host -> Service).

HAS_CREDS (Host -> Credential).

PROTECTED_BY (Host -> Defense).

CONTAINS (Host -> Flag).

TRUSTS (Host <-> Host) : relaciones de confianza de AD.

Cada arista EXPLOITS tiene propiedades: probabilidad de éxito, factor de sigilo, técnica MITRE.

6. Sistema de Agentes
Los agentes son binarios compilados (Go/Rust) que reciben tareas del director vía gRPC y ejecutan módulos.

6.1 Tipos de agentes
Stager: binario mínimo que solo se registra, recibe módulos y los ejecuta en memoria. Ideal para acceso inicial.

Cell: agente completo con módulos de persistencia, C2 camuflado, keylogger, etc.

Pivot: agente que corre en un host comprometido y expone otros segmentos de red.

6.2 Paralelismo
El director mantiene un pool asíncrono de agentes activos. Cuando surge una tarea (ej: escanear un nuevo host), la asigna a un agente libre. La comunicación es dúplex sobre un stream gRPC único por agente, reduciendo latencia.

6.3 Módulos del agente
Reconocimiento: escaneo TCP SYN, HTTP banner grabbing, SMB enum, LDAP enum.

Explotación: ejecución de exploits propios (Go) o delegación a Metasploit vía RPC desde el agente si está habilitado.

Post-explotación: inyección de RAT, despliegue de rootkit, volcado de credenciales, keylogger.

Evasión: AMSI/ETW bypass, unhooking, syscalls directas, sleep obfuscation, Chameleon C2.

CTF: flag hunter (regex), auto-submit, defensive shield.

7. Arsenal de Malware (Factory)
Todos los binarios se generan bajo demanda con un comando argos arsenal build. La fábrica toma plantillas de código (Go/Rust), aplica ofuscación y parámetros específicos.

7.1 Catálogo
Tipo	Lenguaje	Descripción
rootkit	Rust	Driver Windows (DKOM + PPL) o LKM Linux (syscall hook).
rat	Go	Agente persistente con C2 camuflado, shell, keylogger, screenshot, file browser.
virus	Go	Worm que infecta binarios locales y se propaga por USB/red.
trojan	Go	Binario señuelo (PDF, DOCX, EXE) que extrae payload y lo ejecuta silenciosamente.
spyware	Go	Robo de contraseñas de navegadores, cookies, billeteras crypto, historial.
exploit	Go/Python	Exploit autocontenido para una CVE específica, con soporte para evasión en tiempo de compilación.
payload	Go/Rust	Shellcode/stager ofuscado que se puede inyectar en memoria o empaquetar en otros binarios.
webshell	PHP/ASPX/JSP	Shell web con ofuscación de código y persistencia (toca archivos del servidor).
7.2 Pipeline de ofuscación
Al construir un binario, se aplican secuencialmente:

Compilación: Garble (Go) con flags -tiny -literals -seed=random, o Rust con obfstr.

Empaquetado: UPX modificado (entrada mágica cambiada, sección de recursos alterada).

Cifrado: AES-GCM con clave única por misión, incrustada como variable de entorno.

Loader: el binario final puede ser un cargador polimórfico que desencripta y ejecuta en memoria (sin tocar disco).

7.3 Integración con Metasploit
argos start --msf levanta una instancia de msfrpcd y se conecta.

Los exploits de Metasploit pueden ser invocados como cualquier otro módulo.

Las sesiones de Meterpreter se tratan como agentes especiales; Argos puede ejecutar comandos sobre ellas.

Los payloads pueden ser generados por msfvenom y luego pasados por el pipeline de ofuscación de Argos.

8. Chameleon C2 (Comunicación Resiliente)
Protocolo de comunicación entre el director y los agentes:

Transporte: WebSocket sobre TLS 1.3.

Serialización: Protobuf binario.

Camuflaje: El tráfico se envuelve en JSON de telemetría falsa de aplicaciones legítimas detectadas en el host (Teams, OneDrive, Chrome Sync).

Fingerprint: uTLS para emular el JA3 de la aplicación imitada.

Ritmo: El módulo HBE (Human Behavior Emulation) ajusta la frecuencia de los beacons según los patrones de actividad del usuario real para mezclarse con el ruido.

Todo esto es configurable desde el comando arsenal build al definir el perfil del RAT.

9. Modo CTF
Al iniciar con --mode ctf, se activan módulos específicos:

Flag Hunter: los agentes buscan activamente cadenas que coincidan con la regex de la competición.

Auto-Submitter: si se proporciona la URL y API key de CTFd, cada flag se envía automáticamente.

Blitz Profiling: el perfil por defecto es blitz (máxima velocidad, mínimo sigilo).

Defensive Shield: en Attack-Defense, los agentes pueden monitorear los servicios propios y tomar contramedidas (reiniciar servicio, bloquear IP atacante).

10. Plan de Implementación (Roadmap)
Fase 1: Fundación (2 semanas)
Estructura del repositorio.

Protobuf y generación de stubs.

Director básico: Grafo Vivo, comandos CLI (start, status).

Agente Stager Go mínimo (registro y beacon).

Fase 2: Motor de Decisión y Escaneo (4 semanas)
Implementar Planificador A*.

Integrar Qdrant y embeddings para CBR.

Crear árboles de reglas para servicios comunes (SSH, HTTP, SMB).

Agente de reconocimiento completo (Nmap, banner grabbing).

Fase 3: Arsenal y Evasión (6 semanas)
Fábrica de malware: plantillas de RAT, payload, webshell.

Pipeline de ofuscación (Garble, UPX modificado, cifrado).

Chameleon C2 con camuflaje de tráfico.

Integración con Metasploit.

Fase 4: Post-explotación y Pivoteo (4 semanas)
Módulos de persistencia adaptativa.

Keylogger, captura de pantalla, file browser.

Pivoteo automático (SSH/SMB/WinRM).

Despliegue de rootkit.

Fase 5: CTF y Pulido (2 semanas)
Flag Hunter y Auto-Submitter.

Defensive Shield para A/D.

Generación avanzada de informes.

TUI completa.

Fase 6: Beta y Mejoras Continuas
Pruebas en laboratorios (HackTheBox, entornos propios).

Ampliación de la base de casos (Qdrant) con datos de la comunidad.

Soporte a MacOS y arquitecturas ARM.

11. Conclusión
Argos se convierte en una plataforma ofensiva de grado militar, pero ligera y manejable desde la terminal. Su cerebro, aunque no use grandes modelos de lenguaje, es capaz de encadenar tácticas complejas y aprender de cada operación. La fábrica de malware integrada proporciona un arsenal personalizado sin depender de herramientas externas, y la evasión está incorporada en cada capa.
