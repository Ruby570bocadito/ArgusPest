Proyecto "Argos" — Desarrollo y Planteamiento Completo
1. Filosofía y Principios de Diseño
text
“Argos no reemplaza al pentester, lo multiplica.
El humano piensa la estrategia; Argos ejecuta la táctica.”
Principios:

Autonomía táctica, supervisión estratégica: Argos decide el cómo; el operador decide el qué y el cuánto.

Transparencia radical: cada decisión, fallo o éxito está registrado con su justificación.

Adaptabilidad en tiempo real: si algo falla, busca alternativas antes de preguntar al operador.

Amnesia post-compromiso: toda evidencia operacional se limpia al terminar.

Memoria entre misiones: aprende de cada pentest para mejorar el siguiente.

3.4 Detección de Defensas (Fingerprinting Pasivo)
Argos infiere la presencia de defensas sin lanzar una sola alerta:

Indicador	Defensa inferida	Técnica de detección
TTL de paquetes HTTP distinto al OS	WAF o proxy inverso	Análisis de diferencia TTL
Respuesta 403 con cabeceras específicas	Cloudflare, Akamai	Fingerprinting de headers
Puerto 443 responde TLS pero no HTTP	EDR con MITM TLS	TLS handshake sin HTTP
Certificado TLS autofirmado con CA interna	Proxy corporativo	Análisis de cadena de certificados
Latencia anómala en ciertos puertos	Honeypot o IDS en modo inline	Timing analysis
Procesos *falcon*, *sentinel*, *defender*	EDR específico	Enumeración remota vía WMI/DCOM/RPC si hay credenciales
4. Planificador de Rutas de Ataque
4.1 Objetivo
Dado un objetivo final (ej: extraer datos de la tabla clientes en 10.20.5.18), calcular las rutas de ataque factibles ordenadas por una métrica combinada.

4.2 Algoritmo de Planificación
Fase 1: Generación de Grafo de Ataque

Nodos = hosts, servicios, credenciales, vulnerabilidades.

Aristas = técnicas de explotación, movimiento lateral, escalado.

Peso de arista = probabilidad de éxito × factor de sigilo.

Fase 2: Búsqueda Multi-objetivo (A* modificado)

Origen: punto de entrada actual (o "sin acceso" si es el inicio).

Destino: objetivo final.

Heurística: distancia al objetivo + valor de activos intermedios.

Resultado: N rutas candidatas con métricas.

Fase 3: Ranking de Rutas

python
# Pseudocódigo de la función de ranking
def rank_route(route):
    score = 0
    for step in route:
        # Probabilidad de éxito del paso
        prob = step.estimated_success_probability()
        # Factor de sigilo: 1.0 = completamente silencioso, 0.1 = muy ruidoso
        stealth = step.stealth_factor()
        # Valor acumulado de los activos comprometidos
        value = step.asset_value_gained()

        score += (prob * stealth * 0.4) + (value * 0.4) - (step.risk_of_detection * 0.2)

    return score

OBJETIVO: Acceso a BD clientes en 10.20.5.18
PUNTO DE PARTIDA: Acceso inicial en 10.20.1.10 (estación de trabajo, usuario local)

RUTA A (prioridad 0.87):
  1. Escalar a SYSTEM local en 10.20.1.10 (técnica: UAC bypass)
  2. Robar token de sesión RDP de administrador
  3. Pivotar a 10.20.1.5 (servidor de saltos) vía Pass-the-Hash
  4. Enumerar AD → encontrar svc_db_backup
  5. Kerberoasting → crackear password de svc_db_backup
  6. Conectar a 10.20.5.18 vía WinRM con credencial svc_db_backup
  Estimación: 6 pasos, riesgo medio, 45 minutos

RUTA B (prioridad 0.62):
  1. Movimiento lateral a 10.20.5.22 (servidor web en mismo segmento que BD)
  2. Explotar vulnerabilidad en aplicación web (CVE-2024-xxx)
  3. Desde el servidor web, pivotar a la BD vía SQL injection interno
  Estimación: 3 pasos, riesgo alto (exploit público), 20 minutos

RUTA C (prioridad 0.41):
  1. Phishing a administrador de BD identificado en LinkedIn
  2. Reverse shell al recibir apertura
  3. Acceso directo a la BD con credenciales del administrador
  Estimación: 2 pasos, requiere interacción humana, riesgo bajo técnicamente
4.4 Replanificación Dinámica
Si un paso falla (ej: el exploit no funciona o la defensa bloquea el acceso), Argos:

Evalúa si el fallo es definitivo o temporal.

Si es definitivo, recalcula rutas excluyendo el paso fallido.

Si es temporal, espera y reintenta con jitter exponencial.

Solo consulta al operador si TODAS las rutas alternativas tienen riesgo > umbral configurado.

5.2 Árboles de Decisión por Escenario
Argos contiene playbooks tácticos para cada situación común, con árboles de decisión predefinidos que no requieren consultar al orquestador:

Ejemplo: Explotación de un servicio web

text
1. Intentar credenciales por defecto (lista interna)
   ├── Éxito → continuar post-explotación
   └── Fallo →
2. Intentar vulnerabilidades conocidas (CVEs mapeados a versión)
   ├── Éxito → continuar
   └── Fallo →
3. Intentar inyección SQL / comando genérica
   ├── Éxito → continuar
   └── Fallo →
4. Intentar fuerza bruta con diccionario adaptado al contexto
   ├── Éxito → continuar
   └── Fallo → notificar al orquestador "no se pudo explotar servicio web en H-XXX"
Ejemplo: Escalada de privilegios en Windows

text
1. ¿Es Administrador local? → SÍ, saltar a paso de persistencia
2. Enumerar privilegios de token (SeImpersonate, SeDebug, etc.)
   ├── SeImpersonatePrivilege → intentar Potato attack
   │   ├── Éxito → ya es SYSTEM
   │   └── Fallo → siguiente
   └── SeDebugPrivilege → inyectar en proceso SYSTEM
3. Enumerar servicios vulnerables (PowerUp / WinPEAS)
   ├── Servicio con permisos de escritura → modificar binario
   ├── Unquoted service path → exploit
   └── ...
4. Buscar credenciales en archivos (SAM, LSA secrets, creds de navegador)
   ├── Encontradas → intentar con ellas
   └── No encontradas → notificar al orquestador
5.3 Gestión de Errores y Reintentos
Tipo de fallo	Acción automática	¿Notifica al operador?
Error de conexión (timeout)	Reintentar 3x con backoff exponencial	No
Credencial incorrecta	Marcar credencial como inválida, probar siguiente	No
Exploit falla	Probar variante, luego siguiente exploit	No
EDR bloquea acción	Activar evasión mejorada, reubicar C2	Sí (riesgo medio)
Honeypot detectado	Marcar host como peligroso, evitar segmento	Sí (riesgo alto)
3 rutas alternativas agotadas	Solicitar instrucciones al operador	Sí (bloqueante)

7. Memoria Operacional y Aprendizaje
7.1 Base de Conocimiento
Argos almacena todo lo aprendido en cada pentest:

Datos estructurados (SQLite)

text
Tablas:
- exploits: id, cve, software, version, fecha_exito, fecha_fracaso, entorno
- credenciales_comunes: servicio, usuario, password, frecuencia
- defensas_encontradas: edr, version, tecnicas_que_funcionaron, tecnicas_que_fallaron
- rutas_exitosas: origen, destino, pasos, tiempo_total, operador
- falsos_positivos: ip, servicio, motivo
Datos no estructurados (Vector Database)

Embeddings de banners de servicios mapeados a vulnerabilidades.

Embeddings de respuestas HTTP para detección de WAF/IDS.

Embeddings de configuraciones de red para identificación de patrones.

7.2 Aprendizaje entre Misiones
Al iniciar un nuevo pentest, Argos consulta su memoria:

Si en misiones anteriores...	Entonces ahora...
El exploit X funcionó en MSSQL 2022 con parche Y	Prioriza ese exploit
El EDR CrowdStrike detectó la técnica Z	Evita Z y prueba variantes
La red objetivo usa segmentación 10.X.0.0/16	Asume segmentación similar y planifica pivotes
Los administradores usan contraseñas tipo Empresa+ Año	Prueba ese patrón antes que otros diccionarios
7.3 Feedback del Operador como Supervisión
Cuando el operador rechaza una decisión de Argos, el sistema registra:

Qué decisión tomó el humano.

En qué contexto.

Resultado final.

Con suficientes interacciones, Argos afina su modelo de riesgo/beneficio para alinearse con el estilo del operador (más agresivo, más conservador, etc.).

8.2 Generación Automática
Argos genera los informes sin intervención del operador al finalizar la misión (o bajo demanda).

Pipeline de generación:

Recopilar todos los eventos del Bus de Eventos.

Filtrar por relevancia (excluir reintentos fallidos, ruido interno).

Agrupar por táctica MITRE ATT&CK.

Para cada hallazgo, buscar en la base de conocimiento la recomendación de remediación estándar.

Renderizar con plantillas (LaTeX para PDF, JSON para ATT&CK).

12. ¿Por qué este proyecto rompe el statu quo?
No existe un auto pentester real: Las herramientas actuales son lanzaderas de exploits o frameworks de C2, no planificadores autónomos.

Combina IA simbólica (planificación de grafos) con IA conexionista (embeddings, aprendizaje): Argos sabe qué hacer y cómo priorizar según la experiencia acumulada.

Respeta al operador humano: No lo elimina, lo convierte en director de orquesta en lugar de músico.

Resuelve el cuello de botella del Red Team: La escasez de talento ofensivo senior se mitiga con automatización inteligente.
